# SIGAT Multiplatform

SIGAT Multiplatform is a Kotlin Multiplatform application that centralizes training programs, action plans, and administrative workflows for the SIGAT team. A single shared codebase delivers feature parity across Android, iOS, and desktop, leveraging Jetpack Compose Multiplatform for UI and Firebase for backend services.

## Key Features
- Unified authentication and registration experience with Firebase Auth.
- Training program management, including listing, detail inspection, and creation flows.
- Action tracking with reporting utilities and admin tooling for role assignments.
- Responsive Compose layouts that adapt from mobile to large desktop viewports.

## Project Structure
- `composeApp/` — shared Kotlin code organised into `data`, `domain`, `state_holders`, and `ui` packages, plus platform bridges in `androidMain`, `iosMain`, and `desktopMain`.
- `iosApp/` — native wrapper and Xcode project for iOS builds.
- `gradle/`, `build.gradle.kts`, `settings.gradle.kts`, `gradle/libs.versions.toml` — dependency catalog and build configuration.

## Tech Stack
- Kotlin 2.2 + Compose Multiplatform 1.8 for UI.
- Firebase Auth, Firestore, and Storage for cloud services.
- Koin for dependency injection and Coroutines for async flows.
- Coil 3 for image loading and FileKit for cross-platform file dialogs.

## Getting Started
1. Install JDK 17+, Android Studio Koala or newer (with the KMP plugin), Xcode 15+ for iOS, and Gradle wrapper support.
2. Configure `local.properties` with your Android SDK path and any environment-specific flags (see `AGENTS.md`).
3. Ensure Firebase credentials are present in `composeApp/src/androidMain/google-services.json` and iOS entitlements.

## Build & Run
- Android debug: `./gradlew :composeApp:assembleDebug` (installs APK via Android Studio or `adb`).
- Desktop preview: `./gradlew :composeApp:run` to launch a local desktop client.
- iOS: open `iosApp/iosApp.xcodeproj`, select a target device, and build; the shared framework is generated by Gradle on the first sync.

## Testing
Run `./gradlew :composeApp:check` to execute all unit tests and static analysis steps. Place shared tests in `composeApp/src/commonTest/kotlin` and add platform-specific suites in the respective `androidTest` or `iosTest` folders. Follow the naming guide in `AGENTS.md` for new cases.

## Configuration
Runtime secrets should stay outside version control; reference them through `.env` files and hook via `local.properties`. Keep Firebase rules and analytics settings aligned with the environment you deploy to, and disable crash/analytics in debug builds.

## Contributing
Review the contributor guide in `AGENTS.md` for coding standards, testing expectations, and pull-request templates. Use conventional commit prefixes (`feat:`, `fix:`, `chore:`) and include screenshots or logs for UI or analytics changes when opening PRs.
